# 01: 年化收益率（XIRR）

**What to build:** 计算引擎新增资金加权年化（XIRR）纯函数：单基金年化映射 + 整体年化（30 天门槛、异常返回空、已清仓现金流计入整体）；概览/流水页数据契约各新增一个年化字段并在既有数据 handler 组装；概览页持仓明细新增「年化收益率」列，概览/流水两页顶部统计区新增第 5 张卡「年化收益率」，「总收益率」卡改名「累计收益率」。口径与接缝详见 spec.md。

**Status:** resolved

- [x] 计算引擎：XIRR 核心求根 + 单基金年化映射 + 整体年化（`today` 显式入参），按 spec「Testing Decisions」补齐全部手算黄金值用例
- [x] 契约：概览/流水数据契约新增年化字段（按基金代码映射 + 整体年化），无需新增 IPC 通道
- [x] 界面：持仓明细加「年化收益率」列（盈亏比例后、仅份额非零行）、顶部第 5 张卡「年化收益率」（累计收益率卡之后）、「总收益率」卡改名「累计收益率」
- [x] 空态/异常：无数据不渲染统计卡；空值显示「—」，与现有 format 工具行为一致
- [x] 既有测试与功能零回归：现有 compute.test.ts、exportService.test.ts 等全绿；导入对账表标签不变

## Comments

- 实现选边（spec 两处措辞歧义，验收口径）：
  1. 单基金无净值记录 → 单基金年化返回 null（显示「—」），不按「期末估值 0」照常求根。依据 US11「无净值记录…显示「—」」；「无净值记录的持仓市值不计入期末估值」在整体口径下生效（跳过该基金、其余照常求根）。
  2. 已清仓基金（份额为 0、净成本 > 0）单基金年化照常计算（全部现金流 + 期末估值 0）；净成本 ≤ 0 一律返回 null（spec「负净成本返回空」）。持仓明细仅渲染份额非零行，该映射值暂不展示。

- **验收注释**（2026-09-09）：计算层在 `src/engine/compute.ts` 新增三个纯函数（`xirr` 核心求根、`computeAnnualizedReturns` 单基金映射、`computeTotalAnnualizedReturn` 整体年化，`today` 显式入参）；契约层 `OverviewData`/`TxData` 各加一个 `annualized` 字段（`AnnualizedReturnData`：perFund 映射 + total），在 dataIpc 既有 handler 组装，无新 IPC。界面：概览/流水两页顶部第 5 张卡「年化收益率」、持仓明细「盈亏比例」后新增「年化收益率」列、「总收益率」卡改名「累计收益率」（导入对账表与导出 Excel 标签按 spec 不变）。测试：spec「必测用例」9 项全覆盖（含 30 天门槛 29/30 边界、分红再投入、已清仓计入整体、不收敛/负净成本返回空），闭合形式黄金值（10%/15%/21%…）+ golden fixtures 手算值（独立脚本求得）双保险；typecheck 与全量 160 测试绿。

- **打包冒烟验收**（2026-09-09 实测 GREEN，`scripts/check-packaged-app.mjs --manual-dialogs`）：导入 10 基金/69 流水对账全部一致 → 概览卡片 golden（总资产 775,962.32 / 总盈亏 −8,351.48 / 累计收益率 −1.06%）→ **年化收益率卡 −2.55%，与数据库独立 XIRR 现场计算 −2.55% 交叉验证一致** → 持仓明细「年化收益率」列 9 行格式合规（逐行百分比、异常行「—」，截图确认列紧随盈亏比例、红涨绿跌着色正确）→ 交易流水页累计/年化卡一致 → 改流水备注并还原 → 导出三表回读一致 → 数据库 10 基金/69 流水/101 净值。踩坑记录：① electron-builder 下载 electron 包时 GitHub 直连卡死 10 分钟超时，`ELECTRON_MIRROR`/`ELECTRON_BUILDER_BINARIES_MIRROR` 指 npmmirror 后秒过；② 本会话终端无「辅助功能」授权（AppleScript 键盘控制被拒），改用 `--manual-dialogs` 由人完成原生对话框；③ 手动模式首轮失败暴露两处脚本缺陷已修：导入预览等待窗口写死 25s（手动模式改为 DIALOG_TIMEOUT）、备份后缀只有日期（同日重跑会覆盖上一轮备份，改为带小时）；④ 导出对话框手动保存时容易落到临时目录上一级，脚本按约定目录轮询未找到时需把文件挪进预期目录。

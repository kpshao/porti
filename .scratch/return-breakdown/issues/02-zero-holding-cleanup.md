# 02: 清仓基金不再留僵尸行，也不凭空占配置比例

**What to build:** 用户清仓一只基金后，概览的持仓明细表不再出现那行全 0、比例为空的行；需要回顾时可通过「显示已清仓」开关把它找回来，并能继续点进基金详情看完整战绩与历史。同时，某个大类被清空后，「实际投入比例」按该大类当前是否还有市值判定——已清空记 0，不再显示由历史亏损造成的、永远消不掉的偏离。

**Blocked by:** None（可立即开工）

**Status:** resolved

- [x] 默认不显示零持仓基金行；开关打开后可见，且仍可从该行点进基金详情
- [x] 零持仓基金不被删数据、不被从计算中剔除（基金详情入口依赖它存在）
- [x] 大类「实际投入比例」只统计当前仍有市值的持仓；已清空大类的比例记 0、偏离显示「—」（偏离记 0 还是「—」经确认改为后者，见 Comments）
- [x] 引擎测试覆盖：单一大类清仓后比例记 0；混合场景（部分大类清仓）分母正确
- [x] `npm test` + `npm run typecheck` 全绿
- [x] 跑起应用目视确认：清仓基金行消失、开关能找回、大类比例不再显示凭空的偏离

## Comments

**2026-10-13 实现完成**

- **开工前拍板的三处口径**（均与 ticket 字面有出入，用户确认）：
  1. 已清空大类的「偏离」显示「—」而非 0。偏离 = 市值占比 − 目标，清空后照算就是 −目标比例（黄金 −5%），属真实低配提示；记 0 会与「从未配置」的大类口径打架（纯债无持仓仍是 −45%）。故 `deviation = null`，表格渲染「—」不着色。
  2. 已清仓基金放在持仓明细**表尾单独一组**（组名「已清仓」），而非回到所属大类组内。组头「大类市值」显示「—」：份额 ≤ 0 时市值恒为 0 或未知，没有可合计的口径。
  3. 组内只收**交易过**（invested 或 redeemed ≠ 0）且份额 ≤ 0 的基金。真实库里 000385 景顺长城景颐双利A 零流水、份额 0，是「从未建仓」不是「已清仓」，依旧不显示。
- **引擎**：`computeCategoryComparison` 的投入比例分子/分母只统计 `shares > 0` 的持仓（判据用份额而非市值——持仓成本在、净值未录入时市值未知，但钱确实投在里面；用市值判据会让这类持仓的净投入从 100% 基数里凭空消失）。`groupPositionsByCategory` 的过滤由 `shares === 0` 收紧为 `shares <= 0`（超卖负份额一并让位，即 strict-cost-basis spec 遗留的现状问题）。新增 `groupClosedPositions` + `CLOSED_CATEGORY`，与在持分组严格互补（并集 = 有过流水的持仓）。`computeTotals` 与总收益口径零改动，golden fixtures 全绿。
- **契约**：`OverviewData` 新增 `closedGroup: PositionGroup | null`（无已清仓时为 null）；概览页 `showClosed` 纯显示层开关，切换不重新取数，关掉后表格回到默认视图。
- **验收脚本** `scripts/check-zero-holding-cleanup.mjs`（CDP + sqlite3 独立事实来源，照 check-overview-grouping.mjs 模板）实测 **GREEN**，19 项断言全过：默认 8 行 = 库中在持 8 只，000217（已清仓）与 000385（从未建仓）均不占行；开关默认关、点开后表尾出现「已清仓」组（组头「—」、组内正是一 000217、份额 0.00、rowSpan 覆盖整组），全表 9 行 = 在持 + 已清仓；点该行基金名称进得去基金详情（标题「华安黄金ETF联接C（000217）」）、Esc 可关；大类配置对比里黄金 = 投入 0.00% / 市值 0.00% / 偏离「—」，而在持大类的偏离仍是数字、投入比例合计 100%。截图目视确认排版未受影响。
- **测试**：`npm test` 194/194 通过（新增/改写 5 例：清仓大类口径 2 例、负份额过滤 1 例、已清仓分组 2 例），`npm run typecheck` 与 `npm run build` 通过。既有「投入比例/市值占比/偏离计算正确」用例的 fixture 原为 `shares: 0` 却带非零市值（自相矛盾），改为 `shares > 0` 的真实形态，断言值不变。
- **文档**：`CONTEXT.md` 补「已清仓」领域词（写明「从未建仓」不算）；README 功能一览的概览条目补开关说明。导出的「大类配置对比」sheet 走同一引擎函数，口径自动一致（该 sheet 的测试只断言表头）。

**2026-10-13 审查后追加修正**（/code-review 两轴审查，Standards + Spec 并行）

- **导出侧口径未跟上（Spec 轴发现，真缺陷）**：`exportService` 的持仓明细 sheet 仍用 `p.shares !== 0`，而引擎已收紧为在持判据——超卖负份额基金在概览页进了「已清仓」组、在导出里却还列在持仓明细里，注释「与概览页持仓明细同一口径」失真。改为 `shares > 0`，并补一例有牙齿的测试（清仓 + 超卖两只基金都不得混进导出的持仓明细段；临时退回旧判据实测会红）。
- **验收脚本判据与引擎不同源（Spec 轴发现）**：脚本原用「流水笔数 > 0」当「交易过」，引擎用的是 invested/redeemed ≠ 0（只认买卖金额）；只有分红类流水的边缘数据会误判。SQL 改为 `SUM(CASE WHEN type IN ('买入','卖出') THEN amount ELSE 0 END)`。另把「已清仓行份额为 0」断言放宽为 `≤ 0`（引擎定义含超卖负份额，否则真库出现负份额时会假 RED）。
- **判据收敛（Standards 轴，baseline smell）**：`compute.ts` 里「在持 = 份额 > 0」原散在四处，抽成 `isHeld`，与 `hasTraded` 对称；`Overview.tsx` 的二层三元改成 `heldGroups` 变量。
- **spec 同步（Standards 轴）**：`spec.md` 仍写着「按是否还有市值判定」「已清空的大类记 0」，与拍板后的实现不符，已同步为「在持（份额 > 0）判据」+「偏离显示「—」」并标注日期来源；`CONTEXT.md` 补「在持」词条（它已用在界面文案、注释与测试名里）。
- **未采纳**：`PositionGroup.category` 现在可装非大类的「已清仓」组名——判定为可接受（它是「组名」不是「大类」，类型注释与函数注释都已写明），改独立类型或渲染层拼装反而增加接缝；新脚本与 `check-overview-grouping.mjs` 约 150 行样板重复属仓库既有惯例（8 个自包含零依赖脚本）。

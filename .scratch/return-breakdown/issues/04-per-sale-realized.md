# 04: 每一笔卖出各自锁定了多少，看得见

**What to build:** 用户在交易流水页看到每笔卖出行自带一个「本笔已实现」金额，能据此追溯概览那个累计数从哪来；在保存一笔卖出之前，表单里就实时显示本笔已实现收益——在唯一能反悔的时刻知道自己做了什么。口径必须与概览的累计值同源，不得另写一套。

**Blocked by:** 01（列名与卡片名同源）

**Status:** resolved

- [x] 引擎新增按笔计算已实现收益的能力，复用现有成本推进口径（同一套移动加权平均），累计值与此前完全一致
- [x] 交易流水表卖出行显示「本笔已实现」；非卖出行留空
- [x] 卖出表单在保存前实时预览本笔已实现收益
- [x] 引擎测试（手算黄金值）：单笔全清；多次买入 + 部分卖出；清仓后再买一笔再卖；同基金多笔卖出的归属正确
- [x] `npm test` + `npm run typecheck` 全绿

**2026-10-13 审查后修正**（/code-review 两轴：Standards 0 硬性违规、Spec 4 项发现）

- **编辑态预览可能与表列背离（Spec 轴，真缺陷）**：候选流水用占位主键 `MAX_SAFE_INTEGER` 保证「排当日最后」，这只对**新建**成立（新流水 id 最大）；**编辑**一笔已有卖出时保存会保留原 id，若同基金同日还有 id 更大的流水，预览按「排最后」算、表里按原 id 序算，两值背离。修法：`realizedForSale(rows, sale, editingId?)` 加第三参——编辑传原主键，旧行被同 id 的候选取代、位次不变；过滤被编辑行也一并收进引擎（原先靠调用方 `filter`，容易漏）。补测试：同日两笔流水（卖出 id 2、买入 id 3），编辑 id 2 时正确值 80、按占位主键排最后则 30——临时把实现打回旧版实测该用例转红，有牙齿。
- **「同一基金多笔卖出」用例实为跨基金（Spec 轴，真缺口）**：原用例标题写「同基金多笔卖出」，实际 A、B 各一笔；恒等回归虽含同基金多笔，但只校验求和——两笔对调仍绿。补「同一基金多笔卖出：各归各的 id」逐 id 黄金值（20 / 35）。
- **时序约定两份（Standards 轴）**：`costBasisStates` 按 date 稳定排序、`realizedPerSale` 按 (date, id)，同一规则两种表达；`computeStatsSeries` / `computeFundSeries` 另有两份同形 comparator。收敛为模块内唯一的 `byDateThenId`（无 id 的流水退化为按日期稳定排序，与原行为等价），四处共用。既有 golden fixtures 与三个验收脚本回归全绿。
- **静默 catch 范围过宽（Standards 轴）**：表单预览的 `try/catch` 连 `realizedForSale` 的异常一起吞。收窄为只兜 `normalizeTransactionInput` 的校验失败，计算异常不吞。

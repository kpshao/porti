# 概览持仓明细按大类分组

## Problem Statement

概览页持仓明细表的数据顺序是「基金代码升序」（`repo.ts` 的 `ORDER BY code` 一路透传到渲染层），同一大类的基金被代码顺序彻底打散。用户要判断「我在某个大类上持有什么、规模多大」，只能逐行扫「大类」列再在脑子里归拢。

用户的实际管理载体（`投资跟踪.xlsx` 的「持仓概览」表）本身就把大类做成**纵向合并的第一列**——`parse.ts:124` 只在每组首行读大类值、后续行继承，正是电子表格合并单元格的行为。界面的结构与用户的心智模型不一致。

页面下方已有的大类配置对比表只给各类占比与偏离，不给明细，且它自身的行序是 SQLite 对中文走 UTF-8 字节序的副产物（`repo.ts` 的 `ORDER BY category`）——固守+ → 权益 → 流动性 → 纯债 → 黄金，既不是直觉顺序也不是 `CATEGORIES` 的声明顺序。两张表之间没有任何视觉对应关系。

## Solution

持仓明细表把**「大类」与「大类市值」放在最前两列，并按组纵向合并单元格**（`rowSpan` = 组内基金数），浅灰底连成一条组色带；组内按基金代码升序；组间按大类声明顺序。大类配置对比表的行序同步对齐到同一顺序，使两张表可以横向对读。

分组与排序在计算引擎完成（主进程组装进契约），渲染层只做格式化，延续现有接缝。

## User Stories

1. 作为持仓者，我想让同一大类的基金在表格里连续出现，以便一眼看清每个大类下我持有什么。
2. 作为持仓者，我想让「大类」成为第一列并按组合并，以便结构与我的 Excel 原表一致、扫视时不需要重复阅读同一个类名。
3. 作为持仓者，我想让每个大类的市值合计独占第二列，以便不靠心算就知道各类的绝对规模，且这个数有自己的列、不与逐行市值混在一起。
4. 作为持仓者，我想让大类之间按固定顺序排列，以便每次打开概览时组的位置一致、可以形成肌肉记忆。
5. 作为持仓者，我想让组内按基金代码升序排，以便顺序跨刷新稳定、不随行情跳动，并形成肌肉记忆。
6. 作为持仓者，我想让没有持仓的大类不出现，以便表格只呈现真实持仓、不被空壳组拉长。
7. 作为用户，我想让大类值缺失或不在五个标准值内的基金归入「其他」并排在最后，以便数据缺口是可见的，而不是被静默吞掉或混进别的大类。
8. 作为用户，我想让大类配置对比表与持仓明细的组顺序一致，以便两张表里的同一个大类在同一水平线上，眼睛可以横向对读。
9. 作为用户，我想让组头区域在默认窗口宽度下不折行，以便「固守+」不会断成两行、基金名称不会断成两行。
10. 作为用户，我想让组头合计的口径与顶部总资产一致（各类市值相加等于总资产），以便数字之间可以互相验证。
11. 作为用户，我想在某一大类下所有持仓都没有最新净值时看到「—」而不是 0.00，以便不被误读为该类持仓一文不值。
12. 作为用户，我想让目标金额的行内编辑与基金详情入口在分组后行为不变，以便既有操作习惯不受影响。
13. 作为维护者，我想让分组与排序是一条带单测的纯函数，以便边界规则（其他组归置、空组剔除）有回归保障。
14. 作为用户，我想让 Excel 导出的「持仓明细」保持平铺，以便导出结果仍可直接用于二次计算。
15. 作为用户，我想让交易流水、基金详情、收益统计、净值管理等其它页面不受影响，以便本次改动范围可控。

## Implementation Decisions

- **分组键**：`FundPosition.category`，即 `CONTEXT.md` 定义的「大类」，闭集五值 `CATEGORIES`（`src/engine/validation.ts:9`）。不用 `fundType`——它可空、无枚举、无校验、UI 从未展示，拿它做骨架会立刻遇到分组空洞。
- **分组骨架**：以 `CATEGORIES` 声明顺序为准 —— 固守+ → 纯债 → 权益 → 黄金 → 流动性。
- **空组**：某大类当前无持仓（含被 `shares !== 0` 过滤后为空）时，不渲染该组。已清仓基金所在的大类若只剩它一只，该组自然消失。
- **兜底组**：「其他」——`category` 不在 `CATEGORIES` 内的持仓（脏值、空串）全部归入，恒定排在五类之后。
- **组内排序**：**基金代码升序**。代码是主键、不并列，故不需要 tie-break；市值的有无与大小都不影响次序。与导出「持仓明细」同向，界面与导出在同一大类内部排序一致。代价是组内不再"市值最大的排最上"——换来的是顺序跨刷新稳定。
- **列结构（12 列）**：`大类 / 大类市值 / 代码 / 名称 / 份额 / 持仓成本 / 最新净值 / 市值 / 持仓盈亏 / 盈亏比例 / 年化收益率 / 目标金额（元）`。
- **合并单元格**：前两列只在组内第一行渲染，`rowSpan` = 组内基金数；组内其余行不含这两个 `<td>`（该行共 10 格）。`vertical-align: middle`（覆盖 `.table td` 的全局 `top`），浅灰底 `#f2f3f5` 把两列连成组色带。沿用既有色值，不引入新色。
- **列名「大类市值」**：不用「总市值」——后者在本代码里已指全组合（`Totals.totalAssets` 的注释即「总市值」，界面卡片叫「总资产」），而"某大类的市值合计"这个量的既有叫法是「大类市值」（`types.ts` 的 `marketRatio` 注释：「实际市值占比 = 大类市值 / 总市值」）。同名同义，避免一词两义。
- **大类市值口径**：`Σ marketValue ?? 0`，与 `computeTotals().totalAssets`、`computeCategoryComparison` 同口径。组内全无净值时显示「—」（跟随 `formatMoney(null) → '—'` 的既有语义）。
- **默认窗口宽度下的宽度预算**：窗口默认 1280（`src/main/index.ts:9`），内容区约 1020px，而 12 列的内容需求约 1090px。故在 `.table` 之上加 `.table-positions` 修饰类收紧：单元格横向内边距 10px → 6px（12 列省约 96px）、目标金额输入框 110px → 88px（省 22px）。「大类 / 大类市值」两列 `white-space: nowrap`——组标签在任何宽度下都不该折行。窗口缩到 `minWidth` 960 时仍会折行，那是接受的降级。
- **对比表排序**：`computeCategoryComparison` 按 `CATEGORIES` 索引排序，非五值类目排在其后（稳定排序保留其在并集中的相对次序）；`selectCategoryTargets` 去掉 `ORDER BY category`——顺序不属于该函数的契约。
- **接缝**：分组逻辑在计算引擎（`src/engine/compute.ts` 纯函数 `groupPositionsByCategory`），由主进程在 `overview:data` handler 组装进 `OverviewData` 契约。渲染层不调计算函数——现状是渲染层从 engine 只取类型与常量/校验函数，`compute.ts` 只被主进程引用。契约改形的消费方只有概览页；导出自己调计算函数（`exportService.ts:55-56`），不受契约改动影响。
- **样式作用域**：宽度收紧与组标签 `nowrap` 都挂在 `.table-positions` 上，不动全局 `.table`，以免波及「大类配置对比」、收益统计页与交易流水页。

## Testing Decisions

- **好测试的标准**：只测纯函数输入 → 输出的外部行为（组序、组内序、兜底归置、合计值），不测 DOM 结构本身。
- **测试落点**：`src/engine/compute.test.ts`，沿用既有手算黄金值风格。
- **必测用例**：
  - 组序为 `CATEGORIES` 声明顺序——输入顺序被打乱后输出仍按声明序
  - 空大类不产生组；输入全部不在五值内时只剩「其他」一组
  - 脏值与空串归入「其他」且置底
  - 组内按基金代码升序；市值的有无与大小都不影响次序
  - 组头合计 = Σ `marketValue ?? 0`；Σ 全部组头合计 == `computeTotals().totalAssets`
  - 组内全部 `marketValue` 为 null 时合计为空值
  - `computeCategoryComparison` 输出顺序为 `CATEGORIES` 顺序，非五值类目排在其后且保持并集内相对次序
- **渲染层**：仓库无渲染层单测先例，以下由端到端脚本覆盖（见下）。
- **端到端**：`scripts/check-overview-grouping.mjs`（CDP，零新依赖），另用系统 `sqlite3` 直读库作为独立事实来源。断言：表头 12 列且前两列正确；组名无重复；组序为声明序；「其他」置底；每组非空；两个合并列 `rowSpan` = 组内行数且组内其余行只有 10 格；合并单元格为浅灰底 + 垂直居中；逐行基金代码与库内大类交叉验证无跨类穿插；组内代码升序；**默认窗口宽度下无单元格折行**；大类市值 = Σ 组内明细市值；Σ 大类市值 == 顶部总资产。

## Out of Scope

- **表头排序**：持仓明细表当前完全没有排序，组内固定代码升序。要做时另立 issue——仓库已有现成范式（`TransactionTable.tsx` 的 `TxSort`/`toggleSort`/`sortArrow` + `styles.css` 的 `.sortable`）。
- **折叠 / 展开**：组不可折叠。
- **导出的「持仓明细」小节**：保持平铺不变，并保留「大类」列（仍在第三列）。界面与导出的列集合与列序从此不等同，这是接受的——导出是平铺数据快照，供二次计算。注意「大类配置对比」小节不在豁免之列：它与界面复用同一个函数，会同步换序。
- **把「目标金额（元）」列移出持仓明细**：它在理念上属于配置而非持仓，移走可腾出约 130px 彻底解决宽度问题。但那是信息架构改动，不是宽度修复，另立项。
- **小窗口（`minWidth` 960）下的折行**：不修。默认窗口下单行是目标，更窄时的折行是接受的降级。
- **UI 风格改造**：`.scratch/0bdd0ad31a307293fa0aabff248abd54.jpg` 那套视觉语言继续搁置。
- **数据质量治理**：导入器在识别不出类型时静默兜底成 `权益`（`src/importer/parse.ts:343-352`），且 `funds.category` 列无 DB 级 CHECK 约束——这是「其他」组的根因，不在本次范围。
- **其它页面**：基金详情、收益统计、交易流水、净值管理一律不动。

## Further Notes

- 领域词汇沿用 `CONTEXT.md`：「大类」= 资产分类，固定五种；*Avoid*：类别、分类。本次不改词汇表。
- **未定义但被复用的词**：「大类市值」与「总市值」都不在 `CONTEXT.md`。二者在代码注释里已成对出现（`types.ts` 的 `marketRatio`：「实际市值占比 = 大类市值 / 总市值」），本次沿用该用法并把它带到界面上。若日后要收进词汇表，应连同「总资产」（界面卡片标签）一词一并厘清。
- 「其他」组只存在于持仓明细表。大类配置对比表的分组键是 `targets ∪ positions`（`compute.ts`），脏值类目会照原样独占一行——脏值场景下两表的组集合口径不一致，与数据质量治理一并另议。
- 大类市值与顶部总资产的一致性是本次最容易验证的验收点：Σ 各列大类市值必须等于 summary-card 的总资产。

# 基金详情与收益走势

## Problem Statement

用户目前只能看到单基金的当前快照指标（盈亏比例、年化收益率）与整体层面的总资产/累计收益曲线，无法看到**单只基金**收益随时间的变化：何时买入、何时卖出、分红如何影响收益、曲线何时回本。缺少从概览持仓表进入的单基金详情视图（含按日收益走势图）。

## Solution

概览页持仓明细点击基金「名称」→ 打开「基金详情」全屏覆盖层：上方指标行（持仓成本 / 市值 / 持仓盈亏 / 盈亏比例 / 落袋收益 / 年化收益率），下方按日「收益走势」图，可在累计收益率 / 累计盈亏金额两种口径间切换，支持 近1月/近3月/近1年/全部 范围切换，图上标注买入/卖出/分红事件点。

## User Stories

1. 作为持仓者，我想在概览页点击基金名称打开「基金详情」，以便查看单只基金的完整收益情况。
2. 作为持仓者，我想默认看到按日累计收益率曲线，以便直观了解收益走势。
3. 作为持仓者，我想把曲线切换为累计盈亏金额口径，以便看到具体的赚钱/亏钱数额。
4. 作为持仓者，我想在图上看到买入/卖出/分红事件点标注，以便理解曲线台阶与跳变的成因。
5. 作为持仓者，我想悬停曲线点看到该日期的收益率、盈亏金额与市值，以便精确读数。
6. 作为持仓者，我想切换 近1月/近3月/近1年/全部 时间范围，以便聚焦近期走势。
7. 作为持仓者，我想在详情里看到 持仓成本/市值/持仓盈亏/盈亏比例/落袋收益/年化收益率 指标行，以便快速核对单基金关键数字。
8. 作为持仓者，我希望清仓区间（持仓成本为 0）收益率显示断点而非错误数字，金额模式仍可用，以便曲线可信。
9. 作为用户，我希望持仓基金没有净值数据时看到空态提示，以便不出现空白图。
10. 作为用户，我希望新增/修改流水、补录净值后打开详情数据是最新的，与其他页面行为一致。
11. 作为维护者，我希望走势计算是带手算黄金值的纯函数，以便口径有回归保障。

## Implementation Decisions

- **口径**：累计盈亏(t) = 市值(t) − 持仓成本(t) + 落袋收益(t)；市值(t) = 截至 t 的份额 × 截至 t 的最新净值；持仓成本/落袋收益按日截断推进（`applyCostBasis`）。累计收益率(t) = 累计盈亏(t) ÷ 持仓成本(t)，持仓成本 ≤ 0 时为 null（图中断开）。金额模式不受断点影响。
- **字段命名**：引擎沿用 `totalReturn` / `totalReturnRate`；界面标签用术语「累计盈亏」。曲线末点与持仓表「盈亏比例」列口径不同（曲线含落袋收益），不要求对齐。
- **时间轴**：仅该基金有净值记录的日期出点（与 `computeTimeSeries` 语义一致）；曲线分辨率 = 净值数据密度（导入为稀疏快照点，自动抓取只写最新净值）。
- **范围切换**：近1月/近3月/近1年 = 今天往前 30/90/365 天过滤点集；「今天」显式入参，过滤在数据组装层完成。
- **数据获取**：新增 IPC 通道 `fund-detail:data`（入参 fundCode + range）：主进程全表读出 → 引擎计算 → 一次返回；契约类型 `FundDetailData = { position, annualized, realizedIncome, series, events }`（events = 该基金全部流水事件，供图上标注）。打开详情时取数，关闭后状态重置。
- **引擎**：新增独立纯函数 `computeFundSeries(fundCode, funds, transactions, navPoints)`；复用 `sharesAsOf` / `latestNavAsOf` / `applyCostBasis`；指标行复用 `computePositions` 与 `annualizedForFund`；落袋收益取 `applyCostBasis` 状态的 realizedGain + cashDividends。既有函数签名与口径不动（strict-cost-basis 约束）。
- **界面**：概览持仓表「名称」列改链接样式（仅份额非零行可点）；详情为全屏覆盖层（复用 TransactionForm 的 modal-overlay 模式，×/Esc 关闭）；图表复用 Stats 的 `useEChart` 与 `lineChartOption`（必要时抽取共享）；配色/零基线/金额万单位沿用 issue 07-stats-charts 约定。
- **事件标注**：四类流水（买入/卖出/分红现金/分红再投入）以 markPoint 标注（颜色与流水表 tag 同色系），悬停显示类型与日期；仅标注有净值记录的日期，其余事件的影响体现在下一个净值点。
- **空态**：持仓基金无净值记录 → 空态提示；年化收益率空值显示「—」（沿用既有约定）。
- **术语**：CONTEXT.md 新增「基金详情」「收益走势」「累计盈亏」；annualized-return spec「基金详情页不做」边界作废。

## Testing Decisions

- **好测试的标准**：只测函数输入 → 输出的外部行为（手算期望值），不测内部推进细节。
- **测试落点**：计算引擎纯函数测试，沿用既有 compute.test.ts 的手算黄金值风格。
- **必测用例**：单笔买入两日净值上涨的收益率手算值；含卖出与分红现金的累计盈亏（移动加权手算）；分红再投入加份额不加成本；清仓区间收益率 null 且金额为落袋平台；逐日截断（跨日流水顺序）；无净值记录返回空序列；首笔流水前的净值日期点收益率为 null。
- **渲染层**：仓库无渲染层单测先例，界面改动以手工验收清单与既有冒烟脚本覆盖（新增 `scripts/check-fund-detail.mjs` 端到端检查，沿用 check-stats-charts 的 CDP 模式）。

## Out of Scope

- 基准对比线（沪深300 / 整体组合曲线）不做。
- 详情内净值表与流水列表不做（复用专页；后续可做跳转筛选）。
- 时间加权收益率（TWR）不做。
- 已清仓基金详情入口不做（持仓表仅份额非零；其历史已计入整体年化）。
- Stats 页单基金柱状图与详情联动不做。

## Further Notes

- 与 strict-cost-basis 的关系：曲线口径必须沿用 `applyCostBasis`；该 spec 明确「不动 XIRR/时间序列/周收益」——本功能新增基金级序列，不修改既有函数。
- 与 annualized-return 的关系：其 Out of Scope「基金详情页不做」由本功能修订作废。
- 领域词汇沿用 CONTEXT.md：流水（买入/卖出/分红现金/分红再投入）、净值、持仓成本、落袋收益；空值统一显示「—」。

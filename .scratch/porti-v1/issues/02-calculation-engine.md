# 02: 计算引擎（主测试接缝）

**What to build:** 一个纯函数计算模块：输入流水、基金元数据、大类目标、净值历史，输出全部聚合结果——每只基金的累计投入/累计赎回/净投入成本/当前份额/当前市值/持仓盈亏/盈亏比例，总资产/总盈亏/总收益率/落袋收益，5 大类实际投入比例/实际市值占比/偏离，周收益（最新净值记录日 vs ≥7 天前最近记录日），以及由收益快照（市值+日期）重建净值历史的换算。所有业务口径与 spec「核心计算规则」一致。

**Blocked by:** None（可立即开始）

**Status:** resolved

- [x] 计算规则与 spec 一致：手续费含成本、ETF 用净值、分红现金单列不减成本、分红再投入只加份额、简单成本法卖出
- [x] 单元测试通过，其中至少一组 golden values 取自 Excel 持仓概览 9 只基金的份额/市值/盈亏与汇总数字
- [x] 周收益按「最新记录日 vs ≥7 天前最近记录日」口径计算正确
- [x] 快照重建净值（NAV = 快照市值 ÷ 当日累计份额）正确
- [x] 边界处理有明确行为与测试：无流水、无净值、份额为零、除零保护

## Answer

完成。纯函数引擎位于 src/engine/（types/compute/reconstruct + 桶文件），与 Electron 完全解耦，vitest 直接跑（18/18 绿）。golden values 取自 Excel 持仓概览 5 只基金（110017/002009/512890/000217/007824）逐项份额/市值/盈亏 + 汇总，另覆盖卖出、分红现金、分红再投入、大类对比、时间序列、周收益、快照重建与全部边界。卖出按库内约定存负值（金额与份额），引擎直接累加。

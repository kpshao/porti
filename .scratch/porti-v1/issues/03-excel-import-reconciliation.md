# 03: Excel 导入与对账

**What to build:** 用户在「交易流水」页点击导入、选择投资跟踪.xlsx 后：先看到预览清单——自动修复项（基金代码补前导零至 6 位、名称按代码从基金列表重查、快照重建为净值历史）与可疑项（净值 1.0577 的分红再投入行，可当场修改）逐条列出；确认后数据写入数据库，页面立即显示计算出的总资产、总盈亏、总收益率与 9 只基金持仓明细，与 Excel 持仓概览逐项一致。

**Blocked by:** 01（项目脚手架与数据库初始化）、02（计算引擎）

**Status:** resolved

- [x] 预览清单展示所有自动修复与可疑项；1.0577 行可在预览中修改后导入
- [x] 收益快照重建为净值历史（import 来源），覆盖 3–8 月（实际文件为 14 期 92 行，见 Comments 勘误）

## Comments

- **勘误：期数与修复数量**。本 ticket 与 spec 所称「20 期快照」「20 余处丢前导零」与当前 Excel 实际不符：收益明细实为 **14 期 92 行**（2026-03-13 至 2026-08-11），代码补零实为 **14 处**（收益明细中 2065/2009 各 7 行）；交易流水中的「名称公式引用错行」在当前文件中已不存在（VLOOKUP 缓存值全部正确，重查规则仍按 spec 实现并测试）。实现与测试均按实际数据断言。
- **设计决定：持仓概览最新净值导入为当前净值**（spec 未明示，但为本 ticket 验收所必需）。收益明细止于 2026-08-11（该日总市值 758,627.25），而持仓概览的「最新净值」更新至 08-24 之后——若不导入，对账无法达到 775,962.32。故将持仓概览最新净值按 `import` 来源写入净值历史，记录日期取流水最大日期（2026-08-24）。1.0577 可疑行修改净值仅影响流水存档，不改变任何汇总数字（简单成本法下分红再投入净值不参与计算）。
- **范围说明**：大类目标比例（category_targets）与单只基金目标金额随导入入库，为 M4 概览前置数据；收益汇总逐期对账为「与 Excel 对账」的自然延伸。

# Spec: Porti V1 — 个人基金仓位管理桌面软件

Status: ready-for-agent

## Problem Statement

用户是一位理财新手，通过购买基金进行投资，目前使用 Excel（`投资跟踪.xlsx`，5 个 sheet：基金列表/交易流水/持仓概览/收益明细/收益汇总）管理约 80 万元的基金仓位。随着持仓基金增多（已 10 只），Excel 方案的痛点日益突出：

- **净值更新费时**：每只基金的最新净值都要手工查询、逐个录入；
- **收益快照靠手工复制粘贴**：每期快照硬编码十几格市值，成本高、易错；
- **数据质量脆弱**：基金代码丢前导零导致 `#N/A`（`2065` 应为 `002065`）、流水行公式引用错行、快照数值无法追溯；
- **缺少可视化的趋势与配置偏离分析**：收益曲线、大类配置对比全靠人肉维护。

用户需要一个 Mac/Windows 桌面软件，自动化净值更新、流水管理、仓位与收益计算，并一次性迁移 Excel 中的历史数据。

## Solution

开发 **Porti**：基于 Electron 的个人基金仓位管理桌面软件（V1），单窗口 + 侧边栏五个页面：

1. **概览** — 总资产/总盈亏/总收益率 + 持仓明细表 + 5 大类「目标比例 vs 实际投入比例 vs 实际市值占比 vs 偏离」对比；
2. **交易流水** — 买入/卖出/分红现金/分红再投入四类流水的增删改查 + Excel 一键导入入口；
3. **净值管理** — 每只基金的净值历史表 + 一键联网抓取（启动自动抓）+ 手动补录单只；
4. **收益统计** — 总资产曲线、累计收益曲线、周收益、单基金盈亏排序；
5. **设置** — 数据文件位置、导出 Excel/CSV 备份、换机迁移（导出/导入迁移包）、抓取源切换。

核心设计：**净值按「基金 × 日期」存储，一切仓位与收益实时由流水 + 净值历史推导**——彻底消灭手工快照。Excel 历史数据通过「导入前预览确认」一次性迁移，导入后与 Excel 逐项对账。

## User Stories

### 数据迁移与导入

1. As an 投资者, I want 一键导入现有 `投资跟踪.xlsx`（69 笔流水、10 只基金、20 期收益快照）, so that 历史数据无需手工重录
2. As an 投资者, I want 导入前看到异常清单与自动修复预览, so that 我知道哪些数据会被修正、哪些可疑数据需要我拍板
3. As an 投资者, I want 基金代码自动补前导零至 6 位（`2065`→`002065`）, so that 历史 `#N/A` 名称问题被彻底修复
4. As an 投资者, I want 基金名称一律按代码从基金列表重新查询, so that 流水里公式引用错行的错误名称被修正
5. As an 投资者, I want 在导入预览中可当场修改可疑数据（如净值与同期参考值偏差过大的行）, so that 错误数据不会原样进入系统
6. As an 投资者, I want 历史收益快照自动重建为净值历史（NAV = 快照市值 ÷ 当日累计份额）, so that 导入后立即拥有 3–8 月的收益曲线
7. As an 投资者, I want 导入完成后看到与 Excel 的对账结果, so that 确认无误后可放心弃用 Excel

### 交易流水

8. As an 投资者, I want 记录一笔买入流水（日期/基金/金额/份额/净值/手续费/备注）, so that 每次买入都有据可查
9. As an 投资者, I want 记录卖出（赎回）流水, so that 份额与成本被正确扣减
10. As an 投资者, I want 记录分红现金流水, so that 落袋收益被单独统计、不影响持仓成本
11. As an 投资者, I want 记录分红再投入流水（只加份额、成本不变）, so that 分红转投被正确处理
12. As an 投资者, I want 编辑或删除历史流水, so that 录错时能修正，且所有统计实时重算
13. As an 投资者, I want 按基金/日期/操作类型筛选与排序流水, so that 快速找到某笔交易
14. As an 投资者, I want 录入时从基金列表选择而非手输代码, so that 避免输错代码

### 净值管理

15. As an 投资者, I want 一键联网抓取全部持仓基金的最新净值, so that 不再手工逐只更新
16. As an 投资者, I want 打开软件时自动尝试抓取净值, so that 每天打开即是当日最新数据
17. As an 投资者, I want 抓取失败时手动录入某只基金某日的净值, so that 数据永远能补上
18. As an 投资者, I want 查看每只基金的净值历史表, so that 了解净值走势
19. As an 投资者, I want 每条净值记录标注来源（导入/自动抓取/手动）, so that 知道数据从哪来

### 概览

20. As an 投资者, I want 一眼看到总资产、总盈亏、总收益率, so that 掌握整体状况
21. As an 投资者, I want 查看每只持仓基金的份额/净投入成本/最新净值/市值/持仓盈亏/盈亏比例, so that 知道各基金表现
22. As an 投资者, I want 看到 5 大类的目标比例、实际投入比例、实际市值占比与偏离, so that 判断是否需要调整配置
23. As an 投资者, I want 维护大类目标比例与单只基金目标金额, so that 配置对比有基准

### 收益统计

24. As an 投资者, I want 查看总资产与累计收益的历史曲线, so that 了解长期趋势
25. As an 投资者, I want 查看周收益（最新净值记录日 vs ≥7 天前最近记录日的总市值差）, so that 了解近期表现
26. As an 投资者, I want 查看单只基金盈亏排序, so that 识别表现最好与最差的持仓

### 设置与备份

27. As an 投资者, I want 一键导出 Excel/CSV（概览/流水/净值三表）, so that 数据随时可回到表格
28. As an 投资者, I want 知道数据文件存放位置并可更改, so that 备份与迁移方便
29. As an 投资者, I want 全部数据保存在单一 SQLite 文件, so that 拷贝文件即完成备份

### 平台

30. As an 投资者, I want 在 Mac 上通过 dmg 安装运行, so that 日常使用无障碍
31. As an 投资者, I want Windows exe 安装包, so that 换 Windows 电脑也能用
32. As an 投资者, I want 全中文界面, so that 使用无语言障碍

### 换机迁移

33. As an 投资者, I want 一键导出单个「迁移包」文件（全部数据 + 版本信息）, so that 换电脑时一个文件带走全部数据
34. As an 投资者, I want 在新电脑导入迁移包（自动备份现有数据后立即生效）, so that 旧电脑数据完整转移、覆盖前有备份可反悔
35. As an 投资者, I want 新安装首次打开时得到导入引导, so that 换机迁移入口清晰不迷路

## Implementation Decisions

- **技术栈**：Electron + React + TypeScript + electron-vite；存储用 SQLite（better-sqlite3）；图表用 ECharts；打包用 electron-builder（产出 dmg 与 exe）。V1 不签名、打包配置预留签名参数。
- **模块划分**：计算引擎（纯函数领域层，主测试接缝）、Excel 导入解析器、净值抓取器、数据访问层、UI 五页。UI 只做展示与调用，不承载业务逻辑。
- **计算口径与 Excel 逐项对齐**（导入后可对账）：
  - 手续费计入成本：金额 = 份额 × 净值 + 手续费，净投入成本含手续费；
  - ETF 与场外基金统一使用基金单位净值，不引入盘中价格；
  - 分红现金计入「落袋收益」单独列示，不减持仓成本；分红再投入只加份额、成本不变；
  - 卖出采用简单成本法：净投入成本 = 累计买入金额 − 累计赎回金额，不做已实现/未实现盈亏分离（严格成本法留待 V2）。
- **数据模型**（SQLite schema，直接采用此形状）：

```sql
-- 基金
CREATE TABLE funds (
  code TEXT PRIMARY KEY,          -- 6 位基金代码，字符串存储防前导零丢失
  name TEXT NOT NULL,             -- 基金简称
  category TEXT NOT NULL,         -- 资产大类：固守+/纯债/权益/黄金/流动性
  fund_type TEXT,                 -- 基金类型：一级债基/二级债基/偏债混合/ETF/黄金/短债等
  target_amount REAL,             -- 单只基金目标金额（元），可空
  created_at TEXT NOT NULL
);

-- 大类配置目标
CREATE TABLE category_targets (
  category TEXT PRIMARY KEY,      -- 固守+0.25 / 纯债0.45 / 权益0.20 / 黄金0.05 / 流动性0.05
  target_ratio REAL NOT NULL
);

-- 交易流水
CREATE TABLE transactions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,             -- YYYY-MM-DD
  type TEXT NOT NULL CHECK (type IN ('买入','卖出','分红现金','分红再投入')),
  fund_code TEXT NOT NULL REFERENCES funds(code),
  amount REAL NOT NULL,           -- 金额（元）；买入/分红现金为正，卖出为负
  shares REAL,                    -- 份额；买入/分红再投入为正，卖出为负，分红现金为空
  nav REAL,                       -- 成交净值
  fee REAL DEFAULT 0,             -- 手续费（元）
  note TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

-- 净值历史（每基金每日至多一条）
CREATE TABLE nav_history (
  fund_code TEXT NOT NULL REFERENCES funds(code),
  date TEXT NOT NULL,             -- YYYY-MM-DD
  nav REAL NOT NULL,
  source TEXT NOT NULL CHECK (source IN ('import','auto','manual')),
  PRIMARY KEY (fund_code, date)
);
```

- **核心计算规则**（计算引擎的对外契约）：
  - 累计投入 = Σ买入.amount；累计赎回 = Σ卖出.amount；净投入成本 = 累计投入 − 累计赎回
  - 当前份额 = Σ买入.shares + Σ分红再投入.shares − Σ卖出.shares
  - 当前市值 = 当前份额 × 最新净值；持仓盈亏 = 当前市值 − 净投入成本；盈亏比例 = 持仓盈亏 / 净投入成本
  - 落袋收益 = Σ分红现金.amount；总收益 = 持仓盈亏 + 落袋收益；总收益率 = 总收益 / 净投入成本
  - 大类汇总：实际投入比例 = 大类净投入 / 总净投入；实际市值占比 = 大类市值 / 总市值；偏离 = 实际市值占比 − 目标比例
  - 周收益 = 总市值(最新净值记录日) − 总市值(≥7 天前最近的记录日)
  - 历史快照重建：NAV(快照日) = 快照市值 / 当日累计份额（份额由流水截至当日推算）
- **Excel 导入规则**：基金代码统一 6 位字符串补零；基金名称按代码从基金列表重查；收益快照按上式重建为 `import` 来源的净值记录；日期序列号转为 YYYY-MM-DD；跳过空行；所有自动修复与可疑项（如净值与同期参考值偏差 >10% 的行）在预览清单中逐条展示，用户确认后写入。
- **净值抓取**：调用公开行情接口（东方财富/天天基金系），HTTP 超时与解析失败时抛错交由 UI 提示手动补录；抓取结果写入 `auto` 来源。
- **导出**：概览/流水/净值三张表导出为 Excel（中文表头）；CSV 作为附加格式。
- **换机迁移**：迁移包为单个 `.portibak` 文件（无损数据库副本 + `migration_meta` 元信息：应用版本/schema 版本/导出时间）；导入时校验可打开性、元信息、完整性、schema 版本（高于当前拒绝并提示升级，低于当前走预留升级路径），确认后自动备份现有数据（同名格式，放数据目录）再热替换生效（关闭连接 → 替换文件 → 重新打开 → 刷新窗口，失败回退重启）；空库首启弹窗引导导入，可跳过。
- **界面**：全中文；金额显示 2 位小数、净值 4 位、份额 2 位、比例以百分比显示（保留 2 位）。

## Testing Decisions

- **测试原则**：只测外部行为（给定输入 → 期望输出），不测实现细节；UI 层不做自动化测试，V1 手工验收。
- **计算引擎（主接缝）**：单元测试（vitest），golden values 直接取自 Excel 真实数字——导入后总资产 775,962.32、总盈亏 -8,351.48、总收益率 -1.06%，以及 9 只持仓基金逐项的份额/市值/盈亏必须与 `投资跟踪.xlsx` 持仓概览完全一致。
- **Excel 导入解析器（I/O 接缝）**：以真实 `投资跟踪.xlsx` 为 fixture，断言：69 笔流水全部解析、代码前导零修复数量、名称按代码重查结果、快照重建出的净值记录数、可疑判定路径（真实 Excel 中 1.0577 异常行已由用户修正为同期值 1.553，故黄金用例断言可疑清单为空，判定逻辑改由合成工作簿夹具覆盖）。
- **净值抓取器（I/O 接缝）**：mock HTTP 响应测试解析与失败路径，不真实联网。
- **端到端对账（M1 验收）**：真实 Excel → 导入 → 计算引擎 → 与 Excel 逐项比对，全部一致方可进入后续里程碑。
- 代码库为全新项目，无既有测试先例可循。

## Out of Scope

- 定投计划与买入提醒
- 多账户管理（如券商 + 银行分账）
- 货币基金/银行存款的现金管理
- 自动再平衡建议（V1 只显示偏离，不给操作建议）
- 应用自动更新（V1 手动下载新版本）
- 严格成本法：已实现/未实现盈亏分离、移动加权成本
- 应用签名与公证（Apple Developer 账号、Windows 代码签名证书）
- 多用户

以上均为 V2 候选。

## Further Notes

- **里程碑**（分步交付，每步可运行、用户验收后再进入下一步）：M0 脚手架 + 数据模型 → M1 Excel 导入 + 对账 → M2 交易流水增删改查 → M3 净值管理 + 联网抓取 → M4 概览 + 大类配置对比 → M5 收益统计 + 图表 → M6 导出 + 打包 dmg/exe + 使用说明。V1 以 Mac 验收为准。
- **已知数据质量问题**（来自对 `投资跟踪.xlsx` 的解析，导入时按上述规则处理）：收益明细中 20 余处基金代码丢前导零导致 `#N/A`；交易流水中「分红再投入 002009」行的名称公式引用错行（导入时名称按代码重查修复）；该行净值原为 1.0577 与 002009 同期净值（约 1.53）不符，已由用户直接在 Excel 中修正为 1.553；收益快照为手工硬编码的静态值，仅能按快照日重建稀疏净值历史。
- **领域词汇**（沿用 Excel 与产品共识）：大类 = 固守+ / 纯债 / 权益 / 黄金 / 流动性；操作类型 = 买入 / 卖出 / 分红现金 / 分红再投入；净投入成本、持仓盈亏、盈亏比例、落袋收益、周收益。
- **语言约定**：代码注释、界面文案、文档均使用中文；与用户沟通使用中文。

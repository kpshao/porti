# 落袋收益严格成本法（分红现金 + 卖出已实现收益）

## Problem Statement

现状「落袋收益 = Σ分红现金」（v1 简单成本法口径），卖出实现的收益永不体现为落袋——卖出通过「净投入成本 = 累计买入 − 累计赎回」减少净成本，已实现收益与浮动盈亏混在「总盈亏」里，无法区分。

用户的典型工作流：以货币基金（流动性大类，如 007824）作流动资金池——分红现金与再平衡卖出超配的资金买入货基，之后资金池的钱再买入其他基金。用户的心智是「落袋 = 已锁定的收益（分红 + 卖出已实现）」，现状口径下再平衡卖出的收益永远看不到落袋。

## Solution

实现 v1 spec 预留的「严格成本法（移动加权平均）」：

- **落袋收益 = Σ分红现金 + Σ卖出已实现收益**
- **总盈亏改为浮动盈亏** = 总市值 − Σ持仓成本
- 资金池（流动性大类）**不特殊处理**，与其它基金一视同仁

**恒等式**（总收益数值不变，只改拆分口径）：每只基金满足
`costBasis = Σ买入 − Σ卖出消耗成本`，`Σ卖出已实现 = Σ卖出回款 − Σ卖出消耗成本`，故

`浮动盈亏 + 落袋收益 = (市值 − 持仓成本) + (Σ分红现金 + Σ卖出回款 − Σ消耗成本)`
`= 市值 − Σ买入 + Σ卖出回款 + Σ分红现金 = 市值 − 净投入成本 + Σ分红现金`（现状 totalReturn）

**手续费**：库内约定 amount 已含手续费（v1 spec「金额 = 份额 × 净值 + 手续费」），成本法一律用 amount，fee 字段不参与。

**界面命名**：概览/流水页卡片「总盈亏」→「持仓盈亏」；持仓明细列「净投入成本」→「持仓成本」（概览表、导出表、收益统计 tooltip）；汇总行「净投入成本」保留（累计净投入，总收益率分母）。

**总收益率口径**：改为「总收益 / 净投入成本」（净投入 ≤ 0 时 null），与 v1 spec 一致，解决 issue 06 记录的 spec/代码矛盾；同时避免「卖在高点后累计收益率反而下降」。

## User Stories

1. 作为投资者，我想让再平衡卖出的已实现收益计入落袋收益，以便看到「已锁定收益 = 分红 + 卖出已实现」。
2. 作为投资者，我用货基做资金池：分红现金与卖出超配资金买入货基、之后再从资金池买入其他基金，我希望落袋收益不受这些中转操作影响（一次落袋、不再冲减）。
3. 作为投资者，我想让「总盈亏」只反映当前持仓的浮动盈亏，以便区分「浮盈/浮亏」与「已落袋」。
4. 作为投资者，我希望总收益数值保持与现状一致（仅拆分口径变化），以便历史数据迁移与 Excel 对账不受影响。
5. 作为投资者，我希望持仓明细的「持仓成本」与「持仓盈亏 = 市值 − 持仓成本」对得上，以便单基金核对。
6. 作为投资者，卖出亏损时落袋收益可以为负（如实反映），以便口径不粉饰。
7. 作为维护者，我希望成本基础推进是带手算黄金值的纯函数，以便口径调整有回归保障。

## Implementation Decisions

- **成本基础算法**（移动加权平均，每只基金独立推进，按日期升序稳定排序、同日按输入顺序——库内 ORDER BY date, id 同规则）：
  - 买入：shares += s，costBasis += amount（含手续费）
  - 卖出：sold = −shares，proceeds = −amount；sharesBefore ≤ 0 时消耗成本为 0（超卖防护）；否则 `costConsumed = min(costBasis × sold / sharesBefore, costBasis)`（部分超卖钳制）；realizedGain += proceeds − costConsumed；shares 归零时 costBasis 置 0（清仓兜底，消浮点残留）
  - 分红再投入：shares += s，costBasis 不变（0 成本份额拉低均价，其市值在后续卖出时成为已实现收益）
  - 分红现金：cashDividends += amount，不动 shares/costBasis
- **接缝**：计算引擎新增纯函数 `CostBasisState` / `applyCostBasis` / `costBasisStates`（`src/engine/compute.ts`）；`computePositions` / `computeTotals` / `computeStatsSeries` 改造复用；`computeTotals` 签名不变，IPC 契约（overviewTypes/statsTypes/dataIpc）无需改动。
- **字段**：`FundPosition` 新增 `costBasis`；`invested`/`redeemed`/`netCost` 保留（大类配置对比与总收益率分母继续用净投入口径）。`StatsPoint.netCost` 重命名为 `costBasis`（UI 零消费，已确认）。
- **不动**：XIRR / 年化收益率、大类配置对比、净值重建、时间序列总市值、周收益——全部维持现状。
- **对账影响**：真实 Excel 数据（10 基金/69 流水）无卖出、无分红现金 → costBasis = invested，新口径下对账数值全部不变（e2e 测试零改动）。若未来在 Excel 补录卖出再导入，Excel 简单成本法与引擎严格成本法将不一致——以引擎口径为准，Excel 仅作首次迁移基准。
- **命名**：「总盈亏」→「持仓盈亏」（概览/流水卡片、导出汇总行）；持仓明细「净投入成本」→「持仓成本」；落袋收益卡片现状不着色，本次保持（卖出亏损可为负，如实显示）。

## Testing Decisions

- **好测试的标准**：成本基础推进只测函数输入 → 输出的外部行为（手算期望值），不测内部实现细节。
- **测试落点**：`compute.test.ts`（新增「严格成本法 — 移动加权平均」describe + 既有断言更新）、`exportService.test.ts` / `transactionService.test.ts`（文案与字段断言更新，数值不变）。
- **必测用例**：多次买入均价 + 部分卖出获利；部分卖出亏损（落袋含负数）；分红再投入 0 成本拉低均价 → 卖出时其市值成为已实现收益；清仓（shares/costBasis 归 0、pnlRatio null）；清仓后再买；超卖防护（sharesBefore ≤ 0 消耗成本 0、部分超卖钳制）；**货基资金池全流程**（买 A → 涨 → 卖超配 → 买货基 → 货基赎出买 B → 分红，断言落袋/浮动/总收益）；净投入为负 → 总收益率 null；同日多笔按输入顺序。
- **恒等回归**：golden fixtures 与收益统计序列的 totalReturn 期望值全部不变。

## Out of Scope

- 负份额（超卖数据错误）导致持仓不隐藏的现状遗留问题。
- 落袋收益卡片着色（现状不着色，保持）。
- 大类配置对比切换持仓成本口径（继续用净投入）。
- 货币基金/资金池的特殊处理（本期确认一视同仁）。
- 已实现收益的按基金拆分明细视图（概览仅汇总展示落袋收益）。

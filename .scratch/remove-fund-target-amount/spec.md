# 移除单只基金目标金额

## Problem Statement

概览页持仓明细最后一列「目标金额（元）」是单只基金的期望金额，可行内编辑。但它从未参与任何计算或比较：没有偏离、没有达成率、没有排序。真正驱动「大类配置对比」的是另一套数据——大类目标比例（默认 25/45/20/5/5），偏离 = 实际市值占比 − 目标比例。

原始 spec（porti-v1 第 23 条）声称维护它「so that 配置对比有基准」，但实现里单只基金从未有过对比——spec 与实现矛盾。它也不在 `CONTEXT.md` 的词表里，而项目里其他核心概念都有词条：它从未真正进入领域语言。

结果：用户给 9 只基金填了目标金额，却从未拿它做决策；持仓明细却为此多背一列，在 12 列宽度预算下被迫把单元格横向内边距从 10px 压到 6px。

## Solution

从数据模型到界面彻底移除单只基金目标金额：

- 删除 `funds.target_amount` 列（schema 版本 1 → 2，老库迁移前自动备份）
- 删除类型、校验、仓储、计算透传、编辑服务、IPC、preload
- 导入忽略 Excel「目标金额(元)」列，导出不再写「目标金额」列
- 概览持仓明细降为 11 列，行内数字编辑只剩「大类配置对比」里的目标比例
- 回退为 12 列做的宽度压缩（内边距 6px → 10px，删除目标金额输入框宽度规则）

配置目标保留且只存在于大类层：目标比例 + 偏离。

## User Stories

1. 作为持仓者，我想让概览持仓明细只呈现与持仓相关的数据，以便表格不再为无人使用的数字占一列。
2. 作为持仓者，我想在默认窗口宽度下有更宽松的单元格间距，以便基金名称与表头更易读。
3. 作为持仓者，我想让大类目标比例与偏离保持原样，以便配置对比不受影响。
4. 作为用户，我想在升级后第一次启动时无需任何手工操作，以便删列迁移自动完成且失败不阻塞使用。
5. 作为用户，我想在删列前自动留一份数据库备份，以便必要时找回被删除的数值。
6. 作为用户，我想让导入继续支持原 Excel（只是忽略目标金额列），以便现有导入流程不变。
7. 作为用户，我想让导出的概览表不再包含目标金额列，以便导出与界面口径一致。
8. 作为维护者，我想让「配置目标只在大类层」成为一条 ADR 与词条，以便后人不会重新引入这个死字段。

## Implementation Decisions

- **范围**：只删单只基金目标金额；大类目标比例、偏离、默认目标种子全部保留。
- **数据层彻底删除**，不做「只删界面、字段留底」的折中。
- **schema 版本 1 → 2**：`initDatabase` 在 `version < SCHEMA_VERSION` 时执行 1→2 迁移——检测 `funds.target_amount` 是否存在，存在则先 `VACUUM INTO` 生成一致性备份（`porti.db.bak-YYYYMMDD-HHmmss`，含 WAL 内容），再 `ALTER TABLE funds DROP COLUMN target_amount`。备份或删列失败则保持旧版本、下次启动重试；代码不读该列，停在旧 schema 不影响使用。
- **旧迁移包**（数据版本 1）仍可导入：`swapDatabase` 重开时 `initDatabase` 走同一迁移。
- **导入**：按列位置读取，保留原有列号不变，仅不再读取第 8 列「目标金额(元)」。
- **导出**：「概览」sheet 的持仓明细删除「目标金额」列。
- **界面**：持仓明细 11 列；`amountEdits` 状态、`commitTargetAmount`、目标金额列与提示文案删除；`InlineNumberEdit` 保留给大类目标比例。
- **样式**：删除 `.table-positions .inline-edit { width: 88px }`；横向内边距定为 8px（11 列在默认 1280 窗口下刚好放入卡片，10px 会溢出约 32px），纵向沿用全局 8px。保留 `.group-cell` 的 `nowrap` 与分组底色；名称列默认 `nowrap`，卡片内容宽不足 1006px 时（`@container`）表头与名称改为可折行。持仓明细表外包一层 `.table-scroll-x`（`overflow-x: auto`），窄窗口下在卡片内横向滚动，不再溢出卡片；不复用收益统计页的 `.table-scroll`（它带 `max-height: 300px` 的限高滚动）。
- **新建基金**：`FundInput` 去掉 `targetAmount` 字段（本就没有界面入口）。
- **历史文档不回改**：porti-v1 spec 第 23 条与 issue 06 保持原样，ADR-0002 记录取代关系。

## Testing Decisions

- 引擎：`computePositions` 不再输出 `targetAmount`；`normalizeFundInput` 不再接受/校验该字段。
- 服务：删除 `updateFundTargetAmount` 及其测试；`createFund` 插入语句去掉该列。
- 仓储：`selectFunds` 不再查询该列。
- 导入：真实 `投资跟踪.xlsx` 仍能解析 10 只基金，目标金额断言删除。
- 导出：概览 sheet 的持仓明细表头为 9 列，空库同；目标金额相关断言删除。
- 迁移：新增单测——v1 文件库（含 `target_amount` 且有值）打开后列消失、产生 `.bak` 备份、`user_version = 2`；新库无该列；重复启动不再迁移；备份失败时不删列、不升版本。
- 迁移包：旧版（v1）包导入后自动升级到 v2。
- 端到端：`scripts/check-overview-grouping.mjs` 表头改为 11 列，并断言真实库副本启动后自动升到版本 2、删列、生成 `.bak`；新增默认窗口无横向滚动、窄窗口（960 视口模拟）滚动容器在卡片内且可横向滚动两项断言；`scripts/check-data-migration.mjs` 的 v1 夹具同样断言老库启动自动迁移。
- 全量测试 + `npm run typecheck` 绿。

## Out of Scope

- 大类目标比例、偏离算法、默认目标种子不变。
- 不提供单只基金目标金额的替代品（目标偏离 / 达成率）；需要时另立项。
- 不回改历史 spec / issue。
